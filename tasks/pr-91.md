## Findings

### Mechanism, against `freeunit` `origin/master` `0fd928c4`

- **VERIFIED** — Unit forks application processes and never execs them:
  `src/nxt_process.c:705` (`pid = fork()`), child path returns from `nxt_process_setup()`
  with `return 0` and no exec; the only `execve()` in `src/` is `src/nxt_external.c:201`,
  the "external" application type. `src/nxt_capability.c:443` says the same in prose.
  A constructor in `unitd` main is therefore inherited by the router, the controller and
  every application worker. The PR's claim holds.
- **VERIFIED — and it weakens the PR's premise** — the `LOG_ALERT` `syslog()` calls are
  dead code on master. `src/nxt_app_log.c:67-77` is inside `#if 0` (opened at line 40,
  `syslogmsg` declared under `#if 0` at line 23); `src/nxt_log.c:108-118` likewise (line 85).
  `nxt_write_syslog()` is `syslog(priority, "%s", message)` (`src/nxt_file.h:255`) with no
  other caller. `git log -S nxt_write_syslog -- src/nxt_app_log.c src/nxt_log.c` returns
  only the initial commit, so it was never live here.
- **VERIFIED** — Unit never calls `openlog()` or `closelog()` anywhere in `src/`. There is
  no process syslog handle for an application to inherit, so the PR's stated premise
  ("its own alert path writes through the process syslog handle") is false on current
  master. PHP's own `log_message()` goes to the Unit request log (`src/nxt_php_sapi.c:1997`).
- The underlying PHP behaviour is already tracked upstream: `freeunitorg/freeunit#688`
  ("FreeUnit on musl (Alpine) uses 12 to 17 percent more CPU per request") lists
  "closelog() closes fd -1. PHP calls it at every request shutdown" as a musl effect and
  fix 6 as "php-src: call closelog() only if openlog() ran", with next step 5 "report the
  closelog() behaviour to php-src". No FreeUnit-side issue or PR exists for this
  (`gh issue list`/`gh pr list` on `freeunitorg/freeunit` for syslog, closelog, 24308: only
  #688 matches).

### Confirmed defects in the PR (all VERIFIED by reading, none run locally)

1. **Premise quoted as fact and wrong** — `docs/php-syslog.md`, the `php_syslog_host.c`
   header comment and the test module docstring all state that Unit's alert path writes
   through an inherited syslog handle. See above.
2. **Record file unwritable by the worker on a root runner** —
   `test/php_syslog_host.c:55` creates it `0644`, line 62 swallows the failed `open()`.
   The constructor runs in root `unitd`; workers drop to `nobody`
   (`src/nxt_process.c:1287-1296`, `configure:34`, `src/nxt_runtime.c:925`,
   `src/nxt_capability.c:164`). Result: the reachability test fails and the other two pass
   vacuously, with the skip not firing. `public_dir()` on the directory does not help.
3. **`test_php_syslog_opened_by_a_request_is_closed` duplicates the previous test's first
   half** (`test/test_php_syslog_handle.py:342` against lines 327-339) and puts its only
   new assertion behind the skip, so it is unreachable on every PHP that has the bug.
4. Minor: no conftest process-group registration for the extra `unitd`
   (`test/conftest.py:678-680`); SIGKILL instead of the graceful stop; `stderr_file` and
   temp dir leak if `Popen` raises; `'php': 'any'` gives no per-version parametrization
   (`test/conftest.py:201-211`).

### Reviewed and found sound

- `test_php_syslog_shim_is_reachable` cannot pass for the wrong reason (the expected pid
  comes from `getmypid()` in the response, and nothing in `unitd` calls `closelog()`).
- No port or socket collision with the shared conftest `unitd`: the second instance uses
  only unix sockets in its own temp dir, and `pid_by_name()` scopes the descriptor checks
  to the shared main pid (`test/conftest.py:1224-1227`).
- `option.current_dir` (build tree) and `option.test_dir` (shim source) are both correct;
  the CI `test/test_php*` glob picks the file up (`build-test.yml:380`).
- `entries()`'s `^(\d+) {event}$` matches the `<pid> <event>\n` lines written.
- Module-scoped fixture order is fine: `check_prerequisites_module` skips a leg with no
  PHP module before `shim`/`host` are set up.

### Extract to upstream: no

Nothing in this pull request belongs in `freeunitorg/freeunit`. Upstream does not own
PHP's bug, no FreeUnit code is involved (`#if 0`), no runtime behaviour changes, and the
only FreeUnit-coupled sentence in the PR is the one that is wrong. The test's value is as
a tripwire in the repo that hosts the test suite; it cannot be proposed upstream as a
regression test for code upstream does not have. If the premise sentence is corrected and
the PR lands in `freeunit-exp`, the finding belongs in a comment on #688 rather than in a
new upstream issue.
